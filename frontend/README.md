# Konditerskaya Frontend

Клиентское веб-приложение (SPA) для оформления заказов на самовывоз, управления очередью заказов (для сотрудников) и администрирования каталога.

## Стек

* **Core:** React 19, TypeScript 5.8, Vite 7
* **Routing:** React Router 7
* **Tests:** Vitest

## Быстрый старт

Требуется **Node.js >= 20** и **npm >= 10**.

1. Установите зависимости:
   ```bash
   npm install
   ```

2. Создайте файл локального окружения:
   ```bash
   cp .env.example .env.local
   ```

3. Запустите dev-сервер (по умолчанию поднимется на `http://localhost:5173`):
   ```bash
   npm run dev
   ```

## Скрипты

| Команда | Описание |
| :--- | :--- |
| `npm run dev` | Запуск локального сервера разработки с HMR |
| `npm run build` | Проверка типов (`tsc -b`) и сборка production-бандла в `dist/` |
| `npm run preview` | Локальный предпросмотр собранного production-бандла |
| `npm test` | Запуск unit-тестов (Vitest) |

## Переменные окружения

Конфигурация задаётся через `.env.local` (не коммитится в Git) или переменные окружения на этапе сборки:

| Переменная | По умолчанию | Описание |
| :--- | :--- | :--- |
| `VITE_API_URL` | `/api/v1` | Базовый URL REST API. Для локальной разработки без прокси укажите адрес бэкенда, например `http://localhost:8000/api/v1`. |

## Архитектура и ключевые решения

* **Авторизация:** Access JWT хранится исключительно в памяти приложения (`src/api/session.ts`) и не пишется в `localStorage`. При перезагрузке вкладки или получении `401` от API сессия сбрасывается со редиректом на `/login`.
* **Ролевая модель:** Маршрутизация разделена через `ProtectedRoute` на публичную зону (каталог, корзина), клиентскую (`/account/*`, `/checkout`), зону сотрудников (`/staff/*`) и панель администратора (`/admin`).
* **Корзина и расчёты:** Корзина персистится в `localStorage` (`konditerskaya:cart:v1`), но хранит только выбранные конфигурации и количество. Итоговая стоимость, доступность позиций и проверка правил всегда рассчитываются на стороне API перед оформлением заказа.
* **Идемпотентность:** Запрос создания заказа (`POST /orders`) отправляется с заголовком `Idempotency-Key` (`crypto.randomUUID()`), который переиспользуется при сетевых ретраях до изменения состава заказа или контактных данных.

## Структура проекта

```text
src/
├── api/          # HTTP-клиент (fetch-обёртка), эндпоинты и управление токеном в памяти
├── components/   # Layout, роутинг по ролям, UI-состояния и переиспользуемые блоки
├── contexts/     # Глобальное состояние: Auth, Cart, Toast-уведомления
├── hooks/        # Общие хуки (обработка асинхронных экшенов)
├── pages/        # Страницы приложения, сгруппированные по доменам и ролям
├── types/        # Контракты запросов/ответов API и типизация ошибок
└── utils/        # Валидация форм и форматирование (деньги, даты в Europe/Moscow)
```

## Деплой

Приложение собирается в набор статических файлов (`npm run build` -> `dist/`). Для корректной работы клиентского роутинга веб-сервер (Nginx, Caddy и др.) должен отдавать `index.html` на все неизвестные маршруты (fallback) и проксировать `/api/v1` на бэкенд.
